## 优惠券勾选后实付金额不变 Bug 修复
- 根因：后端 `buildCouponVO` 把数据库 `promotions.type`（大写 `DISCOUNT`/`VOUCHER`）原样返回前端，前端 `calcDiscount` 按小写 `discount`/`cashback`/`freebie` 匹配，全部跳过导致 `totalDiscount=0`
- 修复：CouponServiceImpl.java `buildCouponVO()` 中 `vo.setType(normalizeType(promo.getType()))`，统一返回小写类型，前端计算逻辑正常生效
- 附带修复：优惠券规则文本 `buildCouponRuleText` 之前也可能因大小写不匹配显示为空

## 优惠券规则文本显示 null/0 及实付金额不变 —— 二次修复
- 根因：`promotions.rule_json` 里数字被存成字符串（如 `"0.8"`），或 key 名和我预期的（value/discount/reduction）不匹配，导致 `getNumber` 返回 null；前端 JS 中 `totalDiscount += null` 等价于 `+0`，实付金额不变
- 后端 CouponServiceImpl.java：
  - `getNumber()` 增强：兼容 `String` 类型数字（自动 parseDouble/parseInt）
  - `getBoolean()` 增强：兼容 `"true"`/`"1"`/`"false"`/`"0"`
  - `buildCouponVO()` 候选 key 大幅扩容：value 增加 `rate`/`amount`/`money`/`price`；maxDiscount 增加 `cap`/`limit`/`max`；minAmount 增加 `threshold`/`min`
- 前端 order.js：
  - `buildCouponRuleText()` 对 null/0 value 做保护性显示，避免 `null`/`NaN` 暴露在 UI
  - `calcDiscount()` 折扣/满减/赠品三种券在 `value == null || value <= 0` 时直接跳过，防止无效勾选
- 提供 `fix_promotions_rule_json.sql`：直接 UPDATE promo_id 1/2/5/6 的 rule_json 为标准 JSONB 格式
