## 营销活动弹窗第四次修复（catchtap + key-path setData）
- **用户反馈**：第三次修复后问题依然存在，点击 input/picker 弹窗照样消失
- **重新分析**：第三次修复的 `adjust-position` 根因论被证伪。新假设——input/picker 的原生触摸事件穿透到页面层，在微信小程序中可能导致 wx:if 绑定异常或页面层级行为异常
- **修复方案**：微信标准弹窗模式 = 蒙层 `catchtap` + key-path `setData`
  1. **`modal-mask` 加 `catchtap="noop"`**：阻断所有触摸事件穿透到 page 层。这是微信小程序弹窗的标准做法，蒙层必须 catch 事件
  2. **`onFormField` 改用 key-path setData**：`setData({ 'form.name': value })` 替代 `setData({ form: {...form, name: value} })`。避免每次键盘输入都整个 form 对象（含嵌套 ruleJson）重传视图层，大幅降低重渲染开销
  3. **`onRuleField`/`onRuleSwitch`/`onFormSwitch` 同样改用 key-path**：`'form.ruleJson.xxx'` 精准更新
  4. **回加 `noop()` 方法**：供蒙层 catchtap 使用
- **事件流验证**：
  - ✕ 按钮 tap → `bindtap="closeModal"` 先于冒泡阶段执行 → 弹窗关闭 → 冒泡到 mask 被 catch 停止 ✅
  - 取消按钮同理 ✅
  - input tap → 原生层先处理（获焦+键盘）→ webview 层事件冒泡到 mask 被 catch 停止 ✅
  - picker tap → 原生 picker 弹出 → webview 层事件冒泡到 mask 被 catch 停止 ✅

## 营销活动弹窗第五次修复（model:value 双向绑定 — 根除 setData timeout）
- **用户反馈**：第四次修复后仍有问题，且错误日志显示 `Error: timeout at WAServiceMainContext.js`
- **根因确认**：`bindinput` 每敲一个键触发一次 `setData` → 快速打字时 50-100ms 一次 → 逻辑层↔视图层通信桥超时 → 页面崩溃 → `this.data` 重置为初始状态 → `showModal` 变回 `false` → 弹窗消失
- **终极方案**：所有 `<input>` 改用微信内置 `model:value` 双向绑定，完全移除 `bindinput`+`setData`
  - `model:value` 是微信 2.12.0+ 的优化绑定机制，由框架内部批量处理值同步，不会逐键触发通信桥
  - **WXML 改动**：6 个 input 全部从 `value="{{...}}" bindinput="onXxxField" data-field="xxx"` 改为 `model:value="{{...}}"`
  - **JS 改动**：删除 `onFormField()` 和 `onRuleField()` 两个方法（21 行代码）
  - 保留 `onRuleSwitch` 和 `onFormSwitch`（switch 不支持 model:checked）
  - 保留 picker 的 `bindchange`（picker 只触发一次，无 timeout 风险）
  - `submitPromo()` 读取 `this.data.form.name` 等字段，model:value 已自动同步，无需改动
- **改动量**：WXML 6 行改，JS 删 21 行，净减代码
